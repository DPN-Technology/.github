# Contributing to DPN Technology Projects

Thank you for contributing.

Repository-specific instructions take precedence over this organization default.

## Before opening a pull request

1. Keep the change focused.
2. Explain the problem before the solution.
3. Run the repository's documented tests and validation.
4. Update documentation when behavior, setup, security or architecture changes.
5. Record new third-party dependencies and their licenses.
6. Do not commit secrets, generated credentials, customer data or machine-specific sensitive files.

## Pull request expectations

A strong pull request includes:

- **Problem** — what is wrong or missing.
- **Scope** — what the change does and does not do.
- **Verification** — tests, manual checks or evidence.
- **Security impact** — auth, permissions, dependencies, data or network effects.
- **Rollback** — how the change can be reverted or disabled if necessary.

## Dependency policy

Prefer dependencies that are actively maintained and suitable for commercial use. Track third-party components and licenses separately from DPN-owned code.

## Security

Do not disclose exploitable vulnerabilities in public issues. Follow the repository `SECURITY.md` or the organization security policy.
