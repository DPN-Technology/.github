# DPN Technology Visual & Brand System

The DPN visual system is designed to make the organization immediately recognizable while still allowing individual products to have their own identities.

## Core identity

### Primary palette

- **DPN Black** — near-black command surfaces and backgrounds.
- **DPN Red** — identity, active control, authority, alerts and energy.
- **White / soft gray** — readable foreground information.
- **Muted steel gray** — secondary metadata and low-priority information.

Product-specific colors may be used when the product needs its own identity. Examples include purple/cyan for immersive or AI-adjacent experiences and orange for industrial/simulation contexts.

## Signature visual elements

### Binary rain

Binary 1s and 0s represent the digital layer beneath DPN systems.

Use binary as atmosphere, not noise:
- low opacity;
- behind primary content;
- avoid interfering with readability;
- vary density across hero/background assets.

### Red lightning

Red lightning represents execution, energy, change and the willingness to build what does not already exist.

Use it as:
- hero energy;
- section separators;
- visual emphasis;
- directional motion.

Avoid using lightning so heavily that every surface becomes visually identical.

### Radar and topology

Radar, rings, nodes and topology lines represent:
- visibility;
- awareness;
- connected systems;
- command and control;
- network/system relationships.

### Glass / metal depth

DPN interfaces and repository visuals may use:
- layered black surfaces;
- subtle borders;
- inset depth;
- glow;
- metallic/gridded framing.

The goal is depth and hierarchy, not decoration for its own sake.

## Typography

Prefer modern sans-serif fonts for headings and monospace fonts for:
- telemetry;
- labels;
- IDs;
- states;
- commands;
- version and evidence metadata.

Repository SVGs should use broadly available font fallbacks such as:
- `Segoe UI, Arial, sans-serif`
- `Consolas, monospace`

## Motion

When DPN visuals are implemented in applications:
- use motion to communicate state or hierarchy;
- support reduced-motion preferences;
- avoid constant distracting animation;
- do not make a static status look live only because it pulses.

## Truthful visuals

A DPN visual may look advanced, but it should not imply:
- production readiness;
- live health;
- security certification;
- a real customer deployment;
- availability;
- performance;
- compliance;

unless the underlying system actually provides evidence for that claim.

## Product identity

DPN-wide consistency should not erase product identity.

Examples:
- DPN core / control products: black + red.
- Aqua / specialty retail experiences: product-specific purple family.
- Industrial simulation: controlled orange/steel accents.
- Immersive/community experiences: neon purple/cyan where appropriate.

## GitHub presentation

Public repositories should prefer:
1. branded hero;
2. live GitHub metadata badges;
3. capability visual;
4. architecture diagram;
5. real project imagery when available;
6. install/run section;
7. security/release evidence;
8. ecosystem navigation.

Do not fabricate runtime screenshots.
